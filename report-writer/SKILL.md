# report-writer

DOCX는 이 폴더의 스크립트가 규칙을 코드로 강제한다. HWPX·PPTX는 해당 스킬로 만들고 아래 규칙을 따른다.

| 형식 | 생성 방법 |
|---|---|
| DOCX (주력) | `scripts/build_docx.py` (규칙 자동 적용) |
| HWPX | `hwpx-skill` 스킬 + 이 규칙. 글꼴은 함초롬바탕 |
| PPTX | `anthropic-skills:pptx` 스킬 + 이 규칙 (쪽 번호 = 슬라이드 번호) |

## 규칙

**구조** 표지(제목·작성자·날짜) → 목차 → 서론 → 본론 → 결론 → 참고문헌. 제목은 Heading 1/2/3 스타일, 목차는 자동 TOC 필드.

**출처**
- 본문에서 인용한 모든 출처는 클릭 가능한 하이퍼링크.
- 참고문헌에는 제목, 기관, 접속일, URL 모두 기재. 접속일은 실제 확인한 날짜.
- 출처를 못 찾은 내용은 쓰지 말고 "확인 필요"로 표시.

**사실** 수치와 사실은 이번 작업에서 웹 검색으로 확인한 것만 쓴다. 기억에서 꺼낸 수치는 쓰지 않는다.

**서식** 쪽 번호는 모든 페이지 하단, 표지 제외(PPTX는 슬라이드 번호). 글꼴 맑은 고딕(HWPX는 함초롬바탕), 본문 11pt, 줄간격 160%. 표·그림은 번호+캡션(`표 1. ○○ 비교`). 색은 2가지 이내(남색 `#1F3864`, 회색 `#595959`, 본문은 검정).

## 작업 순서

1. **요청 확인**: 주제, 형식, 독자, 분량. 모르면 먼저 묻는다. 기관·작성자·날짜 등은 추측하지 않는다.
2. **조사**: 웹 검색으로 사실을 모으며 항목마다 URL, 제목, 발행 기관을 기록한다. 확인 못 한 항목은 "확인 필요" 목록에 둔다.
3. **명세 작성**: `templates/report_spec.example.json`을 복사해 내용을 채운다. 블록 종류는 아래 참고.
4. **생성**: `python scripts/build_docx.py spec.json 보고서.docx` (`-I`는 쓰지 말 것. 이 스크립트는 사용자가 만든 코드다)
   - 명세 오류(서론/본론/결론 누락, 참고문헌 항목 누락, 참고문헌에 없는 본문 링크)가 나면 고쳐서 다시 실행한다.
5. **점검**: `python scripts/check_docx.py 보고서.docx`. FAIL이 있으면 고쳐서 재생성·재점검한다.
6. **렌더링 점검(필수)**: `python -W ignore scripts/render_docx.py 보고서.docx 출력폴더`. Word(없으면 `--soffice`)로 열어 목차 필드를 갱신하고 PDF·PNG로 변환한 뒤, 쪽 번호(표지 제외·연속), PDF 링크 주석, 목차 쪽수와 실제 쪽수 일치를 자동 확인한다. 이어서 PNG를 직접 열어 표지·목차·표가 있는 쪽을 눈으로 본다.
   - **분량은 글자 수로 추정하지 말고 이 렌더링으로 센다.** (한 번 추정했다가 실제와 8쪽 가까이 어긋났다.) 분량 기준은 요청한 범위(예: 본문 = 서론~결론)로 센다.
   - 분량이 모자라도 근거 없는 내용으로 채우지 않는다. 근거를 더 조사한 만큼만 늘린다.
7. **보고**: 점검 결과, "확인 필요" 항목 목록, 못 한 검증을 사용자에게 그대로 알린다.

HWPX·PPTX는 3~4단계를 해당 스킬로 대체하고 5단계 자동 점검은 건너뛰되, 체크리스트는 수동으로 확인하고 자동 점검을 못 했다고 보고한다.

### 명세 블록 (build_docx.py)
`h1` `h2` `h3` (text) · `p` (text) · `bullets` (items) · `table` (caption, header, rows, note) · `figure` (path, caption, width_cm).
본문 속 `[이름](URL)`은 하이퍼링크, `**굵게**`는 굵게. 참고문헌 섹션은 `references`에서 자동 생성되며, 본문 링크 URL은 모두 `references`에 있어야 한다. 표·그림 번호와 캡션은 자동.

## 스크립트가 보장하는 것 / 아닌 것
- 보장: 표지 분리, 표지 제외 쪽 번호(PAGE 필드, 본문 1쪽부터), Heading 스타일, TOC 필드, 실제 하이퍼링크, SEQ 캡션, 글꼴, 11pt, 160%, 2색.
- 목차의 쪽 번호는 Word가 파일을 열 때 갱신한다. (Word로 저장한 갱신본은 색·글꼴·11pt 설정이 바뀌어 check_docx가 FAIL을 내므로 전달 파일로 쓰지 않는다.) 열면 "필드를 업데이트할까요?" 창이 뜨며 '예'를 누르면 된다. 갱신 전에는 제목 목록만 보인다.
- 사실의 정확성, 출처가 주장을 뒷받침하는지는 코드가 확인하지 못한다. 직접 확인한다.
- 표 안 글자는 10pt·줄간격 1.2다(본문 규칙 예외).
- 줄간격 160%는 Word의 "배수 1.6"으로 구현한다. 맑은 고딕은 글꼴 자체의 줄 높이가 커서 실제 줄 간격이 약 30pt(글자 크기의 2.7배)로 넓게 보이고 쪽수도 늘어난다. 한글(HWP)의 160%(글자 크기의 1.6배)와 기준이 다르므로, 더 촘촘한 간격을 원하면 사용자에게 확인한다.
- 렌더링 점검에서 잡아 고친 문제(재발 방지로 코드에 반영됨): 빈 문단으로 띄운 표지가 2쪽으로 넘침(→ 문단 간격 사용), 목차가 본문 줄간격을 상속해 2쪽 이상 차지(→ TOC 스타일 지정, 내장 스타일 ID), 한글-영문 사이 자동 간격(→ 끔), 표 행이 쪽 사이에서 잘림(→ cantSplit, 머리글 행 반복).

## 완료 전 체크리스트
자동(`check_docx.py`):
- [ ] 구조 순서, Heading 스타일, 목차 필드와 목차 항목 = 실제 제목
- [ ] 하이퍼링크, URL 형식, 참고문헌 항목(제목·기관·접속일·URL)
- [ ] 쪽 번호 존재, 표지에는 없음
- [ ] 표·그림 캡션, 본문 11pt, 줄간격 160%, 글꼴 1종, 색 2가지 이내

수동:
- [ ] 본문 인용과 참고문헌이 1:1 대응하고 링크가 실제로 열린다
- [ ] 모든 수치·사실에 웹 검색 근거가 있다. 없으면 "확인 필요"다
- [ ] 표·그림을 본문에서 번호로 언급했다
- [ ] "확인 필요" 목록을 사용자에게 알렸다
- [ ] `render_docx.py`로 렌더링해 쪽 번호·링크·목차 쪽수 PASS를 확인하고, PNG를 눈으로 봤다(못 했으면 못 했다고 보고)
- [ ] 요청한 분량을 렌더링으로 센 쪽수로 보고했다(추정치 아님)

통과하지 못한 항목을 통과했다고 보고하지 않는다.
